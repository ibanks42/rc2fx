# USB framing fixtures

Shared test vectors for `desktop/usbproto` (Go) and `crates/rc2fx-usb/tests/shared_fixtures.rs` (Rust), with each side testing its own direction. Only Go reads `hello4`, `descriptors`, `requests`, and `replies`, since parsing the mixer's hello ack, checking HID report descriptors for RC2FX reports, encoding requests, and decoding replies are all client-side responsibilities.

- `cases.json`: hello acks (`hello4`), HID report descriptors (`descriptors`), 256-byte reports paired with decoded frames (`frames`, or `null` for invalid frames), OUT transfer lengths (`canonical`, Rust-only since OUT is the mixer's receiving side), request encoding (`requests`, exact wire bytes), reply decoding (`replies`), and request decoding (`requestsIn`). All byte strings are hex.
- `messages/<name>.bin`: packed messages generated by Go's `Pack` (or truncated from it). `cases.json` pairs each with a size limit and either the expected decoded file or an exact error (`*` allows any error when zlib rejects the stream directly).

These were generated once from the Go port; add new cases by hand and verify both test suites agree.
